# 验证说明

在仓库根目录运行以下命令。工具链版本见 [运行说明](../README.md#运行)。浏览器、数据库及工作机的手动验证使用隔离环境和自有素材。

## 自动检查

```sh
pnpm install --frozen-lockfile
uv sync --all-packages --locked
uv run --all-packages playwright install --only-shell chromium
pnpm check
pnpm test
pnpm build
```

| 命令                | 验证范围                                                                        |
| ------------------- | ------------------------------------------------------------------------------- |
| `pnpm check`        | 类型、Lint、包边界、生成的邮件调色板和未使用的导出、CSS 与 token。              |
| `pnpm test`         | Node 单元测试、Vitest 组件测试、FastAPI、媒体与工作机测试，以及真实浏览器回归。 |
| `pnpm test:browser` | 构建当前 Web，在 Chromium 中验证桌面和 320 px 宽度的结果列表及双站切换。        |
| `pnpm build`        | Web 生产资源与平台分发的工作机、Skill 下载包，输出目录为 `dist/`。              |
| `pnpm format:check` | Prettier 和 Ruff 的格式检查。                                                   |

Forgejo 仓库的原生工作机流水线可用 `actionlint -config-file .github/actionlint.yaml .forgejo/workflows/*.yml` 检查。安装 ShellCheck 后，actionlint 也会检查流水线中的 Bash 脚本。

FastAPI 测试使用每个用例的临时 SQLite 和 Alembic 迁移。浏览器回归通过测试工作机协议准备两页结果，从同源 FastAPI 加载生产网页。用键盘打开第二页的结果、切换到下一项并关闭，核对焦点回到原卡片且页面保留滚动位置。在缺少浏览器系统库的 Linux 环境中，安装命令加上 `--with-deps`。本地验证视频封面、短片和画面截取时需要 `ffmpeg` 和 `ffprobe`，缺少这些命令时相关测试会跳过。完整 GPU 执行需要能够运行目标工作流的 ComfyUI 工作机。

用以下命令在 WebKit 和 Firefox 重跑登录、玻璃页头、成品播放、工作流参数与历史导航的回归。普通测试默认使用 Chromium。

```sh
uv run --all-packages playwright install webkit firefox
for engine in webkit firefox; do
  COMFYSHOP_TEST_WEB_ENGINE="$engine" pnpm test:browser \
    -k 'glass_preference or video_player or paged_result or loading_result_parameters or switching_versions or workflow_fullscreen' || exit
done
```

`pnpm test:browser -k workflow_fullscreen` 检查桌面全屏切换时保留表单、参考图和结果，并核对版本链接直达及关闭后的焦点。验证结果列表扩列并随窗口宽度填满内容区，少量作品保留空列。检查全屏和 320 px 下隐藏翻页条，键盘左右方向键仍能切换相邻工作流。在 320 px 验证普通链接和全屏链接都铺满视口，标题栏提供关闭按钮。

`pnpm test:python apps/api/tests/test_asset_library_browser.py` 在桌面、440 px 和 320 px 验证空库上传、工具栏控件对齐、过滤、预览、下载和移出，也核对工作机能读取从资产库选用的原件、结果中的成品可以存入资产库。上传后打开头像菜单，检查容量条和用量刷新。切换到空团队，从工作机页面打开头像菜单，核对团队额度和空容量条，切回个人空间后读取个人用量。

`pnpm test:python apps/api/tests/test_asset_lifecycle.py` 验证用量接口和上传校验共用配额计算，覆盖相同文件去重、跨空间隔离，以及删除和恢复任务后的读数。

`pnpm test:python apps/api/tests/test_projects.py` 在桌面和 320 px 核对顶部导航、项目页头、标签与筛选栏、创建项目、关联工作流与参考素材、生成、作品发布和整批移动。测试从普通生成入口新建项目时核对已填参数，并切换到团队确认列表和路由随空间更新。个人和团队从「项目操作」核对编辑、归档、从已归档列表恢复、删除和撤销，检查焦点和每次操作的提交次数。接口测试覆盖个人共享、团队角色、跨空间归属、归档及删除后的队列和成品保留、操作记录、批次重试、已删除任务的保留结果及公开作品的数据范围。

为两个测试团队设置不同上限，在桌面和窄屏切换空间核对生效额度。在同一团队并发上传两份只能容纳其一的原件，再降低额度，检查已有素材仍可读取、剩余为零、重复原件可以复用。核对复制、从公开作品生成和任务恢复遵循目标团队的额度。

自托管 CI 可在仓库 Secret `COMFYSHOP_TEST_POSTGRES_URL` 中填写 runner 能访问的局域网测试库。连接格式示例为 `postgresql+psycopg://comfyshop_test:<password>@db.lan.example:5432/comfyshop_test`，将示例主机名替换为实际局域网 IP 或主机名。CI 可以读取该 Secret 时优先使用它，其他运行使用作业内的临时 PostgreSQL 17。

本地设置环境变量 `COMFYSHOP_TEST_POSTGRES_URL` 后，运行 `uv run --all-packages pytest apps/api/tests/test_migrations.py apps/api/tests/test_media_restore.py`。前者验证 SQLite 和 PostgreSQL 的空库建表、结构一致性及降级，后者验证将 SQLite 备份导入 PostgreSQL、原件复用和提交回执丢失后的恢复。连接需要在专用测试数据库中创建和删除独立 schema 的权限。

### 工作流详情打开方式

运行 `pnpm test:browser -k workflow_fullscreen_preference`。在桌面和 320 px 宽度从账号菜单开启「工作流弹框默认全屏（实验性）」，核对刷新后的勾选状态及新打开的详情。桌面验证单次退出全屏、关闭再打开和复制全屏链接。关闭偏好后验证全屏链接仍可直达。

### 玻璃材质

登录后，在页头账号菜单的「账号设置」下方开启「玻璃效果（实验性）」。默认关闭，选择保存在当前浏览器的站点存储中。刷新后核对选项和材质，使用新的浏览器会话核对默认外观。

吸顶页头、弹框外壳、菜单、下拉选项、帮助提示、通知和视频预览控制条在浏览器支持背景模糊和颜色混合时使用方角玻璃材质。弹框的背景模糊更强，菜单与提示使用更密的底色。输入框、媒体画布和放大后的成品预览使用实底。支持相应系统偏好检测的浏览器在减少透明度、提高对比度或强制颜色模式下也以实底呈现浮层。

在 Chromium 和 Safari 分别以桌面和 320 px 宽度切换深浅主题。在有明亮封面的列表里打开菜单和弹框，核对文字、输入框与键盘焦点。继续打开嵌套弹框、下拉选择和帮助提示，核对弹层顺序和关闭后的焦点位置。播放并放大成品视频，核对控制条、进度轨和全屏画布。

在 macOS Safari 的普通窗口和全屏中，滚动列表检查页头和浏览器工具栏的衔接。页头顶边与页面底色一致，玻璃高光从页头内部过渡。分别检查深色、浅色和系统提高对比度模式。

### 移动端与无障碍

用 iPhone、iPad Safari 和 Android Chrome 打开登录、搜索和生成参数弹框。弹出软键盘，切换横竖屏并收放浏览器地址栏，检查当前输入、底部操作与关闭按钮仍可通过滚动到达。全屏或从主屏幕启动后检查导航、媒体控制和底部操作避开屏幕安全区。自动化测试可改变可视视口的高度和偏移，核对登录表单的位置与提交。

在 Windows 强制颜色模式下用 Tab 和方向键操作导航、标签及筛选菜单，确认键盘焦点、选中项和任务状态可以辨认。在 Safari 开启 VoiceOver，检查打开和关闭嵌套弹框后的焦点，以及生成通知设置和撤销操作的状态播报。

### 公开链接、参考图和媒体

- 在支持系统分享的浏览器中打开公开工作流与作品，确认分享面板带上当前公开链接。取消分享后仍可复制链接。通过普通局域网 HTTP 打开同一页面，确认手动复制仍可用。
- 聚焦参考图的上传控件后粘贴截图，或者在浏览器允许读剪贴板时使用「粘贴图片」。分别在个人与团队生成表单核对同一套文件格式、大小校验和预览，填入参数并在工作机领取后验证原件。
- 在浏览器支持时从成品播放器进入画中画，切到其他窗口再退出。用系统媒体控制对成品音视频播放、暂停和跳转，回到页面核对进度。关闭播放弹框后检查系统媒体控制不再绑定该预览。

### 安装和生成完成通知

用支持安装的浏览器打开「安装应用」。macOS Safari 从「文件 → 添加到程序坞」安装，iPhone 和 iPad 从浏览器的分享菜单添加到主屏幕。启动后检查图标、独立窗口、深浅主题和登录流程。

通过 HTTPS 访问并在账号菜单打开「生成完成通知」。本机回环地址也可用于桌面验证。iPhone 和 iPad 从主屏幕上的 ComfyShop 启动后开启通知。提交一个个人任务和一个团队任务，关闭 ComfyShop 页面，等工作机完成后检查通知及其任务详情入口。关闭通知、退出登录和切换账号后，后续任务应按对应设备上的会话订阅投递。

`pnpm test:python apps/api/tests/test_browser_app.py apps/api/tests/test_web_push.py` 验证可视视口、安装入口、浏览器订阅、服务工作线程、任务完成、加密、重试和退出登录。自动化用受控推送响应验证服务端，再由浏览器向服务工作线程投递 PushEvent 并核对通知的展示请求和任务地址。系统通知栏和点击回到应用的体验在真实设备上检查。

## 端到端验证

在隔离服务上注册账号并确认邮箱，再用同一实例验证执行流程。

1. 用工作机能访问的平台地址打开「工作机」页并下载启动包，再在浏览器确认接入。观察状态和节点数量。工作机运行自己的 ComfyUI。
2. 导入一个能在该工作机运行的 API JSON 工作流，设置参数并提交。确认任务入队、领取和回传时状态一致。对支持种子的工作流执行两次，检查「提交参数」和两次「生成参数」中的实际值。
3. 在「我的 → 结果」核对每次执行的输出数量、尺寸和来源。下载原文件并与 ComfyUI 输出比较，参考素材可按原比例预览。
   在隔离环境保持平台心跳并暂停工作机与 ComfyUI 的 WebSocket 连接，核对任务显示「连接中断，正在重试」。恢复连接后，核对同一任务完成、原文件可下载，并在 ComfyUI 确认只提交一次。
4. 发布成功执行的工作流版本，并把其中部分成品发布为作品。分别在所有者、其他账号和访客会话核对工作流、作品、原文件和共享参数的权限。
5. 从本人结果载入参数，检查种子和素材。用另一个已登录的账号在新标签直接打开共享了参考素材的作品链接，点击「载入参数」。确认来源版本、参数和已共享素材进入表单，直接提交并核对工作机实际回传。再从工作流的作品列表打开同一作品，核对两种入口。
6. 取消一条未被领取的任务后撤销，并验证队列恢复。对另一条正在执行的任务使用停止操作，确认保留已经完整回传的结果，且旧执行无法恢复排队。
7. 保持工作机进程连接，停止本机 ComfyUI 或提交一个本机任务。在桌面和手机宽度检查工作机及任务详情里的等待原因。从排队任务打开工作机详情，再将任务换到另一台已同步兼容节点的工作机。确认它进入目标队尾，原工作机无法领取这条任务。
8. 提交批次并让途中一组的回传超时，保存 ComfyUI 中的原成品。检查原任务保留此前成功的组。恢复回传后，确认这组补传沿用原 prompt。为其余明确需要重跑的执行提交补跑，核对新任务的次数及逐次种子。
9. 用隔离配置安装后台工作机，退出终端后检查工作机仍在线。让本机 ComfyUI 稍后启动，核对诊断和自动接单。模拟工作机进程异常退出并确认重启，再用同一配置尝试前台启动，核对独占锁。用后台服务验证一次签名更新，最后移除测试服务。

如有视频输出，检查首帧、播放、Range 请求及原文件下载。暂停在另一帧，使用「用当前画面作组封面」，确认结果卡片更新，并在发布时核对沿用的作品封面。

### 两版真实工作机回归

`tooling/e2e.py` 在独立 Compose 项目内启动 Team（PostgreSQL 和 RustFS）与 SQLite（本地数据卷）。每版从站点下载启动 ZIP，核对 `serverUrl` 和 SHA-256 后通过原生入口启动发布者和访客的工作机。浏览器批准配对。访客在桌面和窄屏从作品直链载入共享参考图并生成。测试核对权限、任务状态、ComfyUI 的执行记录和原件 SHA-256。

加上 `--updates` 后，每版先用本次测试签名的启动包接入，再从工作机页面请求更新。先验证签名错误后沿用原版本，并用同一工作机 ID 从桌面提交任务。再验证有效发布的版本、构建标识和本机安装记录，并用同一工作机从窄屏提交任务。两次任务均从作品直链载入共享素材并核对 ComfyUI 原件。两个更新状态各留一张截图。测试发布包由当前源码和锁文件构建，使用测试版本号及当次生成的私钥。

在装有 Docker Compose、Git、uv 和 Chromium 运行依赖的控制机运行。以下是 Linux x64 本地工作机的配置示例。`COMFY_TEST_ORIGIN` 指向已启动、允许写测试素材和成品的真实 ComfyUI 服务。可用 CPU 模式执行这个无需模型的流程。

```sh
uv sync --all-packages --locked
uv run playwright install --only-shell chromium
uv run python -B tooling/e2e.py \
  --root "$HOME/.local/share/comfyshop-e2e" \
  --target linux-x64 --comfy "$COMFY_TEST_ORIGIN" --updates
```

控制机也可通过 `--executor ssh --ssh-host SSH_ALIAS --native-root TEST_ROOT --bind TEST_INTERFACE_IP` 调度其他宿主。测试账号的 SSH 公钥登录和 `known_hosts` 须已配置。Windows x64 提供 `python.exe`，macOS 和 Linux 提供 `python3`。宿主上的工作机分别执行 ZIP 内的 `start.cmd`、`start.command` 或 `start.sh`。每台宿主须能访问测试站点和 ComfyUI。对通过已授权远程桌面连接的测试宿主，`--executor manual` 会在本次运行目录生成私有 `native-ticket.json`，可在实机上用 `python -B tooling/e2e_native.py TICKET_URL TEST_ROOT` 接入。

#### CI 配置

私有 Forgejo 从 `.forgejo/workflows/` 调度工作机回归。公开 GitHub 的常规检查由 `.github/workflows/ci.yml` 执行。

- 在隔离的 Linux x64 runner 注册标签 `comfyshop-e2e-pr`，配置真实 CPU ComfyUI 和 `COMFYSHOP_E2E_PR_COMFY_URL`。在确认测试存储预算后，将 `COMFYSHOP_E2E_PR_ENABLED` 设为 `true`，两版会在 PR 上运行（`.forgejo/workflows/worker-e2e-pr.yml`）。
- 原生回归使用仅维护者能提交工作流的私有仓库。在 macOS arm64、Windows x64、Ubuntu WSL2 x64 各注册一台宿主模式 runner，分别指定 `comfyshop-native-macos`、`comfyshop-native-windows`、`comfyshop-native-wsl2` 标签及 `self-hosted` 标签，每台并发设为 1。各宿主提供 Git，Mac 和 Windows 提供 Node.js。Windows 使用 `cmd.exe` 与 `python.exe`，Ubuntu 使用 Bash 与 `python3`，从 CI 服务器获取本次触发的提交。
- 对无法访问 Python 软件源的宿主，可预装对应架构的 uv 和 Python 3.12，在 runner 环境设置 `UV_OFFLINE=1`，用 `UV_FIND_LINKS` 指向与该工作机包的锁定依赖相符的 wheel 目录。启动与更新仍使用安装器的依赖哈希校验。锁文件变更后同步更新这一目录。
- 在 Mac runner 的环境中配置 `COMFYSHOP_E2E_ROOT`、`COMFYSHOP_E2E_COMFY_URL`、`COMFYSHOP_E2E_BIND` 和 `COMFYSHOP_E2E_SSH_CONFIG`。Mac 提供 uv、Chromium 运行依赖及 Docker Compose。使用受信任的 SSH 主机配置，Windows 和 Ubuntu 分别设置 `COMFYSHOP_E2E_WINDOWS_SSH_HOST`、`COMFYSHOP_E2E_WINDOWS_ROOT`、`COMFYSHOP_E2E_WINDOWS_IP`，以及 `COMFYSHOP_E2E_WSL_SSH_HOST`、`COMFYSHOP_E2E_WSL_ROOT`、`COMFYSHOP_E2E_WSL_IP`。两组 IP 是对应宿主访问控制机时的来源地址。两个远端 runner 各自在本机将 `COMFYSHOP_E2E_NATIVE_ROOT` 设为与控制机配置对应的私有目录，并使用该 SSH 账号运行。
- 将 `COMFYSHOP_E2E_NATIVE_ENABLED` 仓库变量设为 `true`。维护者手动触发 **Real work machine E2E**，`target` 默认覆盖三台宿主，可选单台重跑两版。`COMFYSHOP_E2E_REF` 默认 `main`，可设置为维护者控制的分支名。Mac 启动本机工作机并运行浏览器，通过已有的 SSH 连接交付短期接入票据。另两台 runner 各自在对应的 CI 作业内读取票据，并运行本系统的启动脚本。CI 状态包含控制机结果和对应的远端作业。各组运行两版启动和签名更新。
- 各 runner 的工作目录、原生测试根和控制机 `COMFYSHOP_E2E_ROOT` 使用独立路径。Mac 的 `runs/ci-<运行编号>-<尝试次数>-<目标平台>` 下保存报告和截图，可按运行编号和目标平台取回。CI 服务按实例的 Actions 设置管理作业日志。

#### 存储与回收

启动前记录控制机路径、实机测试根、Docker 构建缓存以及 ComfyUI 的输入和输出位置。`report.json` 含运行编号、Compose 项目名、卷名及大小、原件路径和工作机目录。控制机留存报告、截图和 Compose 日志，原生宿主留存启动包与依赖。退出时停止工作机并移除该测试项目的容器与网络。测试文件和命名卷供操作者决定保留期限。

回收前按报告预览待清范围。选定整次部署后可用该运行保存的 `compose.json` 执行 `docker compose -f COMPOSE_REPORT_PATH --profile '*' down --volumes`。工作机目录、共享缓存和 ComfyUI 原件分别选择。保留报告时可单独回收已登记的测试卷与原件。Compose 配置、工作机状态和手动连接票据含测试凭据，保持在私有目录内。

### Skill 验证

## 类型与 Lint

`pnpm check` 统一执行 TypeScript、ESLint、Pyright、Ruff、包边界和未使用代码检查。修改 API 契约后运行 `pnpm api:generate`，修改设计 tokens 后运行 `pnpm tokens`，再检查生成文件的差异。

Ruff 除语法和未定义名外，还检查常见缺陷（B）、异步代码中的阻塞调用（ASYNC）、FastAPI 写法（FAST）、导入顺序（I）、旧语法（UP）和安全问题（S）。`assert` 只用于类型收窄的不变量，权限和输入校验必须显式抛错。确需例外时在行内写明原因，规则配置见根目录 `pyproject.toml`。

`pnpm check:infra` 用 actionlint、hadolint 和 shellcheck 检查 CI 工作流、`Dockerfile` 和 shell 启动脚本，三个命令需另行安装。CI 下载固定版本并校验 SHA-256。`.hadolint.yaml` 不检查 apt 包版本固定，因为 Debian 会撤下被安全更新替换的旧版本。

### 未使用代码

- Knip 核对 Web、共享包、测试和 JavaScript 工具脚本的引用，OpenAPI 生成声明豁免未使用类型报告。
- Vulture 核对 API、工作机、Skill、测试和 Python 工具，动态入口和序列化字段按仓库配置声明。
- CSS 和 token 按源码引用检查，由 `tooling/check-styles.mjs` 实现。实际布局与交互通过浏览器验证。

## 重复代码与安全扫描

额外安装 jscpd、支持 pnpm 12 锁文件的 OSV-Scanner，以及支持按规则限定例外的 Gitleaks 8.25 或更新版本后，在仓库根目录运行：

```sh
pnpm check:duplicates
pnpm check:deps
pnpm check:secrets
pnpm check:secrets:staged
```

重复代码报告供人工审阅。依赖扫描读取 `pnpm-lock.yaml` 和 `uv.lock`。密钥扫描分别检查本地提交历史和已暂存变更，输出隐藏命中的密钥值。仓库的 `.gitleaks.toml` 启用默认规则并检查工作机 API Key，已核实的两处误报按规则、文件和内容限定。

验证所用的服务地址、密钥、账号凭据、数据库、备份和运行日志保存在仓库外。
