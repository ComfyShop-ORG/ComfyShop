# 验证说明

在仓库根目录运行以下命令。工具链版本见 [运行说明](../README.md#运行)。浏览器、数据库及工作机的手动验证使用隔离环境和自有素材。

## 自动检查

```sh
pnpm install --frozen-lockfile
uv sync --all-packages --locked
pnpm check
pnpm test
pnpm build
```

| 命令                | 验证范围                                                           |
| ------------------- | ------------------------------------------------------------------ |
| `pnpm check`        | 类型、Lint、包边界、生成的邮件调色板和未使用的导出、CSS 与 token。 |
| `pnpm test`         | Node 单元测试、Vitest 组件测试、FastAPI 和工作机的 pytest 测试。   |
| `pnpm build`        | Web 生产资源与平台分发的工作机、Skill 下载包，输出目录为 `dist/`。 |
| `pnpm format:check` | Prettier 和 Ruff 的格式检查。                                      |

FastAPI 测试使用每个用例的临时 SQLite 和 Alembic 迁移。工作机协议、断线恢复和前端交互也有自动测试。本地验证视频封面、短片和画面截取时需要 `ffmpeg` 和 `ffprobe`，缺少这些命令时相关测试会跳过。完整 GPU 执行需要能够运行目标工作流的 ComfyUI 工作机。

设置 `COMFYSHOP_TEST_POSTGRES_URL` 后运行 `uv run --all-packages pytest apps/api/tests/test_media_restore.py`，可验证两种数据库从首版建库、SQLite 备份导入 PostgreSQL、原件复用和提交回执丢失后的恢复。测试连接需要在专用测试数据库中创建和删除独立 schema 的权限。

## 端到端验证

在隔离服务上注册账号并确认邮箱，再用同一实例验证执行流程。

1. 用工作机能访问的平台地址打开「工作机」页并下载启动包，再在浏览器确认接入。观察状态和节点数量。工作机运行自己的 ComfyUI。
2. 导入一个能在该工作机运行的 API JSON 工作流，设置参数并提交。确认任务入队、领取和回传时状态一致。对支持种子的工作流执行两次，检查「提交参数」和两次「生成参数」中的实际值。
3. 在「我的 → 结果」核对每次执行的输出数量、尺寸和来源。下载原文件并与 ComfyUI 输出比较，参考素材可按原比例预览。
4. 发布成功执行的工作流版本，并把其中部分成品发布为作品。分别在所有者、其他账号和访客会话核对工作流、作品、原文件和共享参数的权限。
5. 从本人结果载入参数，检查种子和素材。用另一账号从公开作品载入已共享参数，补齐参考素材后重新提交。
6. 取消一条未被领取的任务后撤销，并验证队列恢复。对另一条正在执行的任务使用停止操作，确认保留已经完整回传的结果，且旧执行无法恢复排队。

如有视频输出，检查首帧、播放、Range 请求及原文件下载。暂停在另一帧，使用「用当前画面作组封面」，确认结果卡片更新，并在发布时核对沿用的作品封面。

### 两版真实工作机回归

`tooling/e2e.py` 在独立 Compose 项目内运行 Team（PostgreSQL 和 RustFS）和 SQLite（本地数据卷）。每版下载站点的工作机启动包，核对 `serverUrl` 和 SHA-256，再运行系统对应的启动脚本并在浏览器配对。测试从另一个账号在桌面和窄屏打开作品直链，载入共享参考图并提交，核对 ComfyUI 的执行历史和成品原件哈希。

控制机需要 Docker Compose、Git、uv 和 Chromium 的运行依赖。以下为 Linux x64 的本机验证示例。`COMFY_TEST_ORIGIN` 指向可写入测试输入和成品的真实 ComfyUI 服务。

```sh
uv sync --all-packages --locked
uv run playwright install --only-shell chromium
uv run python -B tooling/e2e.py \
  --root "$HOME/.local/share/comfyshop-e2e" \
  --target linux-x64 --comfy "$COMFY_TEST_ORIGIN"
```

跨机器验证可指定 `--executor ssh --ssh-host SSH_ALIAS --native-root TEST_ROOT --bind TEST_INTERFACE_IP`。可用 `--ssh-config` 选择已配置公钥和主机校验的连接文件。Windows x64 提供 `python.exe`，macOS 和 Linux 提供 `python3`。实机须能访问测试站点及 ComfyUI。

运行前选定控制机和实机的存储路径、Docker 构建缓存及 ComfyUI 输入输出范围。`report.json` 记录 Compose 项目、卷名、原件路径和工作机目录。退出时释放测试容器和网络，保存报告、截图、日志和命名卷。卷和运行目录可按报告中的路径逐项回收。原生工作机状态和 Compose 配置含测试凭据，存放于受限目录。

### Skill 验证

运行 `uv run --all-packages pytest apps/api/tests/test_skill.py` 检查安装包、会话、提交重试和命令对应的 API 行为。手动验证在隔离平台打开 `/skill`，执行终端对应的安装命令并登录，从自己的客户端查询工作流、提交两组输入，在「我的 → 任务」和「我的 → 结果」核对记录。

### 建库与升级验证

将 `COMFYSHOP_DATA_DIR` 指向隔离目录。验证 SQLite 新建库时使用空目录，验证 PostgreSQL 新建库时将 `COMFYSHOP_DATABASE_URL` 指向独立空库。从仓库根目录运行建库和结构检查。

```sh
pnpm db:migrate
uv run --package comfyshop-api alembic -c apps/api/alembic.ini check
```

验证后续版本升级时使用待升级数据库和原件的同一时点副本，核对升级前后的账号、工作流版本、任务、执行、素材绑定和作品可见范围。用原文件哈希核对媒体，用 SQLite 的 `PRAGMA foreign_key_check` 检查引用。

## 网络与认证验证

- 用实际部署的域名或局域网地址访问，验证注册、登录、刷新保留会话和退出。明确配置 Host 白名单后，未列入的主机名应被拒绝。检查来自其他 Origin 或缺少 CSRF 的认证写请求被拒绝。
- 在「账号设置」更换邮箱，先确认旧邮箱仍有效，再通过新邮箱的链接确认。核对链接过期、成功后的重复访问及未配置 SMTP 时的日志交付。
- 检查工作机接入、重置与撤销使用当前服务地址。重置后旧凭据失效，运行中的任务结束，密钥更新后可继续领取仍在队列中的任务。配置方式见 [部署说明](deployment.md)。
- 在隔离环境用同一公钥签发工作机版本。运行旧版，执行任务时点「更新到最新版」，再发布更高版本。核对成品回传后选择的是此时的最新版。另验证获取清单后、下载前发布新版本，旧包已清理且工作机能重新获取。分别验证成功切换和校验或启动失败后继续领取，核对工作机 ID、实际版本及更新状态。

## 界面验证

用同一构建在桌面和手机宽度检查，建议使用 1280 × 900 和 390 × 844，并在 320 px 检查导航和账号设置。涉及输入聚焦和局域网 HTTP 剪贴板时，使用真实的移动 Safari。

- 首页、搜索和账号菜单可用。登录框保留 Logo，关闭后焦点回到触发控件。手机聚焦密码、搜索或参数输入时保持原比例。
- 用无外观记录的浏览器验证默认深色，切换浅色并刷新后直接显示浅色。在桌面和 320 px 窄屏检查页头搜索与外观按钮、登录弹框、个人资料和工作机页。核对主题切换后媒体上的字幕与控制按钮可读。
- 从账号菜单打开「个人资料」，用横图或竖图测试上层裁剪弹框的拖动、缩放和方向键。取消后核对原头像和昵称草稿，保存后核对头像与预览一致，昵称通过「保存昵称」单独更新。在 320 px 宽度核对裁剪预览和操作按钮可访问。
- 从公共、个人和收藏列表打开工作流，检查前进、后退、筛选和滚动位置。打开共享链接时核对工作流权限，打开作品链接时核对选中的作品。剪贴板无法自动复制时，检查弹框显示可选择的完整链接。
- 打开工作流和任务详情，检查窄屏时标题、状态、筛选和底部操作可访问，长标题、错误信息或选项不会让弹框横向溢出。
- 在「我的结果」为 FLAC 和 GLB 上传封面或选择成品图。检查列表标识、原件播放或预览及下载。发布时核对所选成品和封面，改结果封面后确认作品保留发布时的图片。再从作品详情更换或恢复封面，核对工作流入口和访客在撤回作品后的权限。
- 在默认、高级和隐藏区移动参数，保存后刷新，核对作者设置、重置默认值、必传素材约束及键盘操作。切换工作机后，确认字段继续使用兼容控件。
- 用包含 `ResolutionSelector` 的文生图调整画幅和 MP，核对预计宽高与实际成品。用 Fibo 图像编辑切换自动、自定义和重置参数。用 P-H3 文生图改画幅和描述，查看提交值中的比例首行，未编辑的历史重跑应保留记录值。
- 在 H3 多参考帧表单核对每张图与时间的位置，缩短目标时长使末帧越界，再调到有效范围。确认网页就地提醒，直接提交越界值返回 422。
- 在 Pixal3D 四视图上传符合图中裁切区域的拼图，核对四个框的位置与名称。替换为尺寸不足的图，确认实际尺寸和越界提示可见。
- 在 MoGe 中选「深度图」并核对提交值为 `depth`。在 Pixal3D 中检查贴图分辨率与简化面数旁的说明。
- 打开「本次参数」，核对各分组和只读参数的当前值默认展开。按显示名、原始字段名和提示查找字段，核对取消、应用和已修改筛选。通过直链打开有历史结果的工作流，从「我的结果」载入参数，核对历史值成为面板初始值。切换到缺少某个模板选项的工作机，核对待处理筛选和改选后的提交值。
- 在桌面和手机宽度打开隐藏参数组，检查标题与开关的布局和提示换行。开启「允许编辑」，核对风险提示和输入控件。修改一项再关闭开关，确认该项回到只读且提示已保留改动。分别测试取消、应用、点击生成区的修改数和「恢复初始值」，核对本次提交使用的值。切换到不支持该选项的工作机后，通过待处理改选可用值。
- 检查媒体列表分页、横竖图比例、预览和下载。桌面悬停视频卡片检查短片与恢复封面，触屏和减少动态效果模式检查静态封面。用键盘切换列表项、关闭嵌套弹框和恢复焦点。
- 在任务或媒体详情检查删除、撤销及引用冲突。无匹配任务时可通过「查看全部任务」恢复列表。
- 在 `/skill` 切换客户端与终端，检查安装命令与下载包。检查工作机页的首次接入、手动添加及密钥操作。

## 类型与 Lint

`pnpm check` 统一执行 TypeScript、ESLint、Pyright、Ruff、包边界和未使用代码检查。修改 API 契约后运行 `pnpm api:generate`，修改设计 tokens 后运行 `pnpm tokens`，再检查生成文件的差异。

### 未使用代码

- Knip 核对 Web、共享包、测试和 JavaScript 工具脚本的引用，OpenAPI 生成声明豁免未使用类型报告。
- Vulture 核对 API、工作机、Skill、测试和 Python 工具，动态入口和序列化字段按仓库配置声明。
- CSS 和 token 按源码引用检查，由 `tooling/check-styles.mjs` 实现。实际布局与交互通过浏览器验证。

## 重复代码与安全扫描

额外安装 jscpd、支持 pnpm 12 锁文件的 OSV-Scanner，以及支持按规则限定例外的 Gitleaks 8.25 或更新版本后，在仓库根目录运行：

```sh
pnpm check:duplicates
pnpm check:deps
pnpm check:secrets
pnpm check:secrets:staged
```

重复代码报告供人工审阅。依赖扫描读取 `pnpm-lock.yaml` 和 `uv.lock`。密钥扫描分别检查本地提交历史和已暂存变更，输出隐藏命中的密钥值。仓库的 `.gitleaks.toml` 启用默认规则并检查工作机 API Key，已核实的两处误报按规则、文件和内容限定。

验证所用的服务地址、密钥、账号凭据、数据库、备份和运行日志保存在仓库外。
